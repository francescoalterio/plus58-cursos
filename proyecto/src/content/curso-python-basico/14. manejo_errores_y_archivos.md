# 12. Manejo de Errores y Archivos

Los errores (excepciones) ocurren cuando algo va mal: dividir entre cero, abrir un archivo que no existe, convertir texto inválido a número, etc. Si no los manejas, el programa se detiene. Con `try/except` puedes reaccionar y seguir.

---

## 12.1 Estructura básica

```python
try:
    x = int("123")  # Código que puede fallar
except ValueError:    # Error específico
    print("No se pudo convertir a entero")
else:
    print("Todo salió bien")
finally:
    print("Fin (siempre se ejecuta)")
```

- `try`: lo que quieres intentar.
- `except`: qué hacer si falla con ese tipo de error.
- `else`: se ejecuta solo si NO hubo error.
- `finally`: siempre se ejecuta (para limpiar recursos).

---

## 12.2 Varios except y excepción genérica

```python
try:
    resultado = 10 / 0
except ZeroDivisionError:
    print("No puedes dividir entre cero")
except (TypeError, ValueError):
    print("Error de tipo o valor")
except Exception as e:  # Último recurso
    print("Error inesperado:", e)
```

---

## 12.3 Lanzar tus propias excepciones

Cuando algo no tiene sentido en tu función, puedes avisar:

```python
def dividir(a, b):
    if b == 0:
        raise ValueError("El divisor no puede ser cero")
    return a / b
```

## 12.4 Errores comunes explicados fácil

| Error               | Cuándo pasa           | Ejemplo                 |
| ------------------- | --------------------- | ----------------------- |
| `ValueError`        | Valor no válido       | `int("hola")`           |
| `TypeError`         | Tipo incorrecto       | `len(5)`                |
| `ZeroDivisionError` | Dividir entre 0       | `10/0`                  |
| `IndexError`        | Índice fuera de rango | `[1,2][5]`              |
| `KeyError`          | Clave inexistente     | `{"a":1}["b"]`          |
| `FileNotFoundError` | Archivo no existe     | `open("x.txt")`         |
| `PermissionError`   | Sin permisos          | Abrir archivo protegido |

## 12.5 Trabajo con archivos (persistencia)

`open(ruta, modo, encoding)` abre un archivo.
Modos más usados:

- `"r"`: leer (falla si no existe)
- `"w"`: escribir (crea o sobreescribe)
- `"a"`: añadir al final
- `"x"`: crear (falla si ya existe)
- Añade `"b"` para binario (imágenes, etc.)
- Añade `"+"` para lectura y escritura

Siempre usa `with` para cerrar automáticamente:

```python
with open("datos.txt", "w", encoding="utf-8") as f:
    f.write("Hola\n")

with open("datos.txt", "r", encoding="utf-8") as f:
    print(f.read())
```

Leer línea a línea (eficiente para archivos grandes):

```python
with open("datos.txt", "r", encoding="utf-8") as f:
    for linea in f:
        print(linea.strip())
```

Escribir varias líneas:

```python
lineas = ["Uno", "Dos", "Tres"]
with open("lista.txt", "w", encoding="utf-8") as f:
    for l in lineas:
        f.write(l + "\n")
```

## 12.6 Manejo de errores al abrir archivos

```python
ruta = "inventario.txt"
try:
    with open(ruta, "r", encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print("No existe el archivo")
except PermissionError:
    print("Sin permisos para leerlo")
```

## 12.7 Ejemplo práctico: inventario simple

Formato: `nombre,cantidad`

```python
# Crear o sobrescribir
with open("inventario.txt", "w", encoding="utf-8") as f:
    f.write("Laptop,10\n")

# Añadir
with open("inventario.txt", "a", encoding="utf-8") as f:
    f.write("Mouse,50\n")

# Leer y mostrar
with open("inventario.txt", "r", encoding="utf-8") as f:
    for linea in f:
        nombre, cant = linea.strip().split(",")
        print(nombre, cant)
```

Actualizar un producto: leer todo, modificar en memoria, escribir de nuevo.

---

## 12.8 Buenas prácticas

- Usa `with` siempre.
- Captura errores específicos primero.
- Incluye `encoding="utf-8"` para textos con acentos.
- Valida datos antes de convertir.
- No uses `except Exception` salvo como último recurso.

## 12.10 Resumen súper simple

- Excepción = señal de que algo falló.
- `try/except` evita que el programa muera de golpe.
- Archivos: `with open(...)` para leer y escribir seguro.
- Siempre piensa: ¿qué puede fallar aquí? y maneja ese caso.

Con esto tu código es más robusto y confiable.
